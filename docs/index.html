One platform, clear boundaries

Apps use Airo. Airo uses the right foundation.

Applications stay independent while common contracts for interface, storage, device capability, media, intelligence, and native work remain reusable. This lets a focused module grow without becoming a separate platform.

  1. 01
    Focused modules

    Purpose-built experiences such as Aika Stream, each designed for a real user journey.

  2. 02
    Airo platform

    Shared UI, capability, data, device, security, and release foundations.

  3. 03
    Runtime and native engines

    Flutter surfaces connect to worker and native boundaries when work needs them.

  4. 04
    User-authorized services

    Modules connect to sources and services only through explicit product boundaries.

Shared foundations

The platform is visible in every module, not hidden behind a logo.

These are architectural foundations, not promises that every capability ships in every product today. Each module declares what it needs and what it deliberately leaves out.

Flutter UI framework

Reusable navigation, design, accessibility, and device-aware presentation patterns.

Native performance boundary

A Rust core and worker boundaries for work that benefits from measured native execution.

Intelligence interfaces

Shared AI and model-routing contracts for modules that choose to adopt them.

Capability composition

Build profiles and module contracts keep each experience focused on its intended devices.

Packs and extensions

A future-facing direction for optional experiences, themes, and community contributions.

Public documentation

Release evidence, guides, decisions, and roadmap work stay connected to the product story.
